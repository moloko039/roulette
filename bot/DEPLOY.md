# Деплой на Railway

Один сервис, один процесс: в нём работают и API для мини-аппа, и бот (через webhook).

Пометка **не проверено** означает, что я не нашёл этого в документации Railway и не пробовал на практике. Такие места сверьте с наставником.

## Как это работает

1. Telegram присылает сообщения боту POST-запросом на `PUBLIC_URL/telegram/webhook`.
2. Сервер проверяет секрет в заголовке `X-Telegram-Bot-Api-Secret-Token` и кладёт сообщение в очередь бота. Ответ 200 уходит сразу.
3. Бот достаёт сообщение из очереди и вызывает обработчик (`/start`, `/balance`).
4. Мини-апп обращается к `GET /api/me` с заголовком `Authorization: tma <initData>`.

## Шаги

### 1. Репозиторий
Код уже в GitHub. В репозиторий не попадают `.env`, `.venv/`, `*.db` — проверьте, что их там нет.

### 2. Создайте сервис
Railway → New Project → Deploy from GitHub repo → выберите репозиторий.

В настройках сервиса (Settings) укажите **Root Directory = `bot`**. **Не проверено**: где именно эта настройка называется и находится в интерфейсе, документацию по ней я не открывал.

Railway сам найдёт `requirements.txt` (проверено по документации Railpack). Версию Python берёт из файла `bot/.python-version` (в нём `3.9`; проверено: Railpack читает `.python-version`; без него по документации берётся 3.13.2). **Не проверено**: что запись `3.9` без патч-версии принимается.

Команда запуска и проверка работоспособности заданы в `bot/railway.toml` (ключи `startCommand` и `healthcheckPath` есть в документации «config as code»). **Не проверено**: подставляет ли Railway `$PORT` в `startCommand` и подхватит ли он файл, если корень сервиса `bot`.

### 3. Том для базы
SQLite хранит игроков в файле, а файловая система контейнера стирается при каждом деплое. Нужен том (Volume).

1. Создайте том: Command Palette (⌘K) или правый клик по холсту проекта → Volume → привяжите к сервису (проверено по документации).
2. Путь монтирования (Mount Path) укажите, например, `/data` (проверено: путь нужно задать самому).
3. Переменная `DB_PATH=/data/players.db`.

Том подключается при запуске контейнера, а не при сборке (проверено). Если бот не может писать в `/data`, в документации советуют переменную `RAILWAY_RUN_UID=0` (написано для образов с не-root пользователем, **не проверено**, нужна ли она вам).

### 4. Число экземпляров = 1
SQLite рассчитана на один экземпляр сервиса. Реплик должно быть **1**. Railway и так не позволяет реплики вместе с томом (проверено по документации: «Replicas cannot be used with volumes»).

### 5. Секрет webhook
На своём компьютере:

```
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Результат — это `WEBHOOK_SECRET`. Никому не показывайте и не коммитьте.

### 6. Публичный адрес
Settings → Networking → **Generate Domain** (проверено по документации Railway). Получится адрес вида `https://something.up.railway.app`. Он нужен в `PUBLIC_URL`.

### 7. Переменные
Задайте в Variables сервиса. **Не проверено**: точное название раздела в интерфейсе.

| Переменная | Пример | Зачем |
|---|---|---|
| `BOT_TOKEN` | `123456:ABC...` (из @BotFather) | токен бота и проверка подписи мини-аппа |
| `WEBHOOK_SECRET` | результат команды из шага 5 | секрет webhook |
| `PUBLIC_URL` | `https://something.up.railway.app` | адрес сервиса, без `/` на конце. Включает режим webhook |
| `WEBAPP_URL` | `https://moloko039.github.io/roulette/` | адрес мини-аппа для кнопки «Играть» (нужен боту) |
| `ALLOWED_ORIGINS` | `https://moloko039.github.io` | откуда мини-апп может обращаться к API (через запятую, `*` нельзя) |
| `DB_PATH` | `/data/players.db` | файл базы на томе |
| `LOCAL_POLLING` | не задавайте на Railway | только для локальной отладки |

`PORT` Railway задаёт сам.

Если `PUBLIC_URL` задан, а `WEBHOOK_SECRET` нет, сервис не запустится (так и задумано).

### 8. Проверка
1. В логах деплоя должна появиться строка «Бот запущен в режиме webhook».
2. Откройте `https://<ваш-адрес>/health`: ответ `{"ok": true}`.
3. Напишите боту `/balance`: придёт баланс и минуты до начисления.

Если сервис не стартует, в логе будет строка «Не удалось зарегистрировать webhook: <тип ошибки>» или сообщение о незаданной переменной. Токен и секрет в логи не попадают.

## Режимы запуска

| Условие | Режим |
|---|---|
| задан `PUBLIC_URL` | **webhook**: бот получает сообщения POST-запросами (продакшен) |
| `PUBLIC_URL` нет, `LOCAL_POLLING=1` | **polling**: бот сам опрашивает Telegram, внутри того же процесса |
| ничего не задано | **только API**, бот отключён (так работают тесты) |

### Осторожно: polling снимает webhook
Режим polling (`LOCAL_POLLING=1`) удаляет webhook у бота: Telegram не отдаёт сообщения одновременно двумя способами. Если запустить его локально с токеном **боевого** бота, бот на Railway перестанет получать сообщения, пока вы не перезапустите сервис (при старте он зарегистрирует webhook заново). Для отладки заведите отдельного тестового бота у @BotFather.

## Локальный запуск

Только API (без бота):

```
cd bot
.venv/bin/python api.py
```

С ботом через polling (тестовый бот!):

```
LOCAL_POLLING=1 .venv/bin/python api.py
```

Адрес по умолчанию 127.0.0.1:8000. На Railway адрес `0.0.0.0` и порт `$PORT` задаются командой запуска в `railway.toml`.
