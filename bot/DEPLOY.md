# Деплой на Railway

Один сервис, один процесс: в нём работают и API для мини-аппа, и бот (через webhook).

Пометка **не проверено** означает, что я не нашёл этого в документации Railway и не пробовал на практике. Такие места сверьте с наставником.

## Как это работает

1. Telegram присылает сообщения боту POST-запросом на `PUBLIC_URL/telegram/webhook`.
2. Сервер проверяет секрет в заголовке `X-Telegram-Bot-Api-Secret-Token` и кладёт сообщение в очередь бота. Ответ 200 уходит сразу.
3. Бот достаёт сообщение из очереди и вызывает обработчик (`/start`, `/balance`).
4. Мини-апп обращается к `GET /api/me` с заголовком `Authorization: tma <initData>`.

## Шаги

### 1. Репозиторий
Код уже в GitHub. В репозиторий не попадают `.env`, `.venv/`, `*.db` — проверьте, что их там нет.

### 2. Создайте сервис
Railway → New Project → Deploy from GitHub repo → выберите репозиторий.

В настройках сервиса (Settings) укажите **Root Directory = `bot`**. **Не проверено**: где именно эта настройка называется и находится в интерфейсе, документацию по ней я не открывал.

Railway сам найдёт `requirements.txt` (проверено по документации Railpack). В нём версии разделены по `python_version`: на Python 3.12 (Railway) свежие fastapi, starlette, anyio, click, python-dotenv, на 3.9 (локально и в CI) последние, что выпускаются под 3.9. Обновления зависимостей присылает `.github/dependabot.yml` (pip в `/bot` и github-actions, раз в неделю). Версию Python берёт из файла `bot/.python-version` (в нём `3.9`; проверено: Railpack читает `.python-version`; без него по документации берётся 3.13.2). **Не проверено**: что запись `3.9` без патч-версии принимается.

Команда запуска uvicorn в `bot/railway.toml` содержит флаги `--no-access-log` (адреса запросов с параметрами, например поиском по имени, в лог не попадают) и `--no-server-header` (нет заголовка `server`). Не убирайте их. Команда запуска и проверка работоспособности заданы в `bot/railway.toml` (ключи `startCommand` и `healthcheckPath` есть в документации «config as code»). **Не проверено**: подставляет ли Railway `$PORT` в `startCommand` и подхватит ли он файл, если корень сервиса `bot`.

### 3. Том для базы
SQLite хранит игроков в файле, а файловая система контейнера стирается при каждом деплое. Нужен том (Volume).

1. Создайте том: Command Palette (⌘K) или правый клик по холсту проекта → Volume → привяжите к сервису (проверено по документации).
2. Путь монтирования (Mount Path) укажите, например, `/data` (проверено: путь нужно задать самому).
3. Переменная `DB_PATH=/data/players.db`.

Том подключается при запуске контейнера, а не при сборке (проверено). Если бот не может писать в `/data`, в документации советуют переменную `RAILWAY_RUN_UID=0` (написано для образов с не-root пользователем, **не проверено**, нужна ли она вам).

### 4. Число экземпляров = 1
SQLite рассчитана на один экземпляр сервиса. Реплик должно быть **1**. Railway и так не позволяет реплики вместе с томом (проверено по документации: «Replicas cannot be used with volumes»).

### 5. Секрет webhook
На своём компьютере:

```
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Результат — это `WEBHOOK_SECRET`. Никому не показывайте и не коммитьте.

### 6. Публичный адрес
Settings → Networking → **Generate Domain** (проверено по документации Railway). Получится адрес вида `https://something.up.railway.app`. Он нужен в `PUBLIC_URL`.

### 7. Переменные
Задайте в Variables сервиса. **Не проверено**: точное название раздела в интерфейсе.

| Переменная | Пример | Зачем |
|---|---|---|
| `BOT_TOKEN` | `123456:ABC...` (из @BotFather) | токен бота и проверка подписи мини-аппа |
| `WEBHOOK_SECRET` | результат команды из шага 5 | секрет webhook |
| `PUBLIC_URL` | `https://something.up.railway.app` | адрес сервиса, без `/` на конце. Включает режим webhook |
| `WEBAPP_URL` | `https://moloko039.github.io/roulette/` | адрес мини-аппа для кнопки «Играть» (нужен боту) |
| `ALLOWED_ORIGINS` | `https://moloko039.github.io` | откуда мини-апп может обращаться к API (через запятую, `*` нельзя) |
| `DB_PATH` | `/data/players.db` | файл базы на томе |
| `LOCAL_POLLING` | не задавайте на Railway | только для локальной отладки |
| `GAME_LINK` | `https://t.me/<бот>/<приложение>` | прямая ссылка на мини-апп (необязательная). По ней игра открывается из групповых чатов и получает данные беседы для рейтинга. Должна начинаться с `https://t.me/` и без пробелов, иначе считается незаданной |
| `PRIVACY_URL` | `https://moloko039.github.io/roulette/privacy.html` | адрес политики конфиденциальности (необязательная, `https://...`) |
| `DEVELOPER_CONTACT` | `dev@example.com` или `@username` | контакт разработчика для команды `/developer_info` (необязательная) |
| `PLAY_MODE` | `card` (по умолчанию), `link` или `button` | как бот отвечает на `/play` и `/start` в группе (необязательная, описание ниже) |
| `TOMBSTONE_SECRET` | результат команды из раздела «Защита от повторной регистрации» | секретный ключ для хэшей удалённых игроков. **Обязательна для `/deletemydata`**; без неё удаление отключено |
| `MEMBER_REF_SECRET` | случайная строка (необязательная; `python3 -c "import secrets; print(secrets.token_hex(32))"`) | ключ HMAC для непрозрачных меток участников беседы (`member_ref`, переводы). Не задана: берётся производный от `TOMBSTONE_SECRET`, если и его нет, ключ случайный на время работы процесса (метки не переживают перезапуск, клиент просто обновляет рейтинг) |
| `OWNER_CHAT_ID` | `123456789` | числовой Telegram-id владельца: уведомления о копиях (см. раздел «Резервные копии»), скрытые команды `/backupnow`, `/give`, `/grantall`, получатель комиссии за переводы и владелец без суточных лимитов переводов (необязательная; при неверном значении всё это отключено) |
| `WRITE_RATE_PER_SEC` | `5` (необязательная) | ограничение частоты для запросов-действий (вращение рулетки и будущие игровые POST): сколько запросов в секунду на игрока восстанавливается |
| `WRITE_RATE_BURST` | `20` (необязательная) | сколько таких запросов подряд можно сделать сразу (размер «пакета») |
| `READ_RATE_PER_SEC` | `10` (необязательная) | то же для чтения (`/api/me`, `/api/chat/top`) |
| `READ_RATE_BURST` | `40` (необязательная) | размер пакета для чтения |
| `SQLITE_JOURNAL_MODE` | не задана (необязательная) | `wal` включает режим WAL (быстрее COMMIT на томе), `delete` возвращает прежний; не задана: ничего не меняется (см. раздел «Режим WAL»). Другое значение: предупреждение при старте, поведение как у не заданной |

`PORT` Railway задаёт сам.

**Ограничение частоты запросов** (`ratelimit.py`, общее для всех игр): токен-бакет в памяти на пару (игрок, группа «write» или «read»). Лимиты щедрые: ручная игра их не достигает, останавливаются только клиенты, шлющие запросы в цикле. Проверка идёт после проверки подписи, неподписанные запросы бакетов не создают. При превышении ответ 429 с телом `{"error": "too_many_requests"}` и заголовком `Retry-After` (секунды, не меньше 1). Повторы с тем же `request_id` тоже считаются. Неверное значение переменной заменяется умолчанием, при старте одно предупреждение с именем переменной. Бакеты без обращений 10 минут удаляются, всего не больше 50 000. Счётчики хранятся в памяти одного экземпляра (реплика одна), после перезапуска сбрасываются.

Необязательные `GAME_LINK`, `PRIVACY_URL` и `DEVELOPER_CONTACT`: если переменной нет (или `GAME_LINK` в неверном формате), связанная с ней команда отвечает «Эта функция пока недоступна», а при старте в лог пишется одно предупреждение с именами недостающих переменных. Сервис при этом работает.

Если `PUBLIC_URL` задан, а `WEBHOOK_SECRET` нет, сервис не запустится (так и задумано).

### 8. Проверка
1. В логах деплоя должна появиться строка «Бот запущен в режиме webhook».
2. Откройте `https://<ваш-адрес>/health`: ответ `{"ok": true}`.
3. Напишите боту `/balance`: придёт баланс и секунды до следующего начисления.

Если сервис не стартует, в логе будет строка «Не удалось зарегистрировать webhook: <тип ошибки>» или сообщение о незаданной переменной. Токен и секрет в логи не попадают.

## Команды бота

Бот отвечает только в личных чатах, группах и супергруппах, в каналах молчит. При старте команды регистрируются в меню Telegram: для личных чатов `start, play, balance, help, privacy, developer_info, mydata, deletemydata`, для групп `play, balance, help, privacy, developer_info`. Ответы без Markdown и HTML. В группах `/play`, `/start`, `/help`, `/privacy`, `/developer_info` отправляются сообщением без цитаты (из темы форума в ту же тему), цитата команды только у `/balance`. `/play`, `/start`, `/help`, `/privacy` и `/developer_info` в группе ограничены: один ответ на чат раз в 20 секунд (общий счётчик).

| Команда | Где | Что делает |
|---|---|---|
| `/start` | личный чат | кнопка «Играть» (мини-апп) и строка «Список команд: /help» |
| `/start`, `/play` | группа | текст со ссылкой `GAME_LINK` и кнопка «Играть» (обычная URL-кнопка). Не чаще одного ответа на чат раз в 20 секунд |
| `/play` | личный чат | как `/start` |
| `/balance` | личный чат | баланс и секунды до следующего начисления (до ближайшей минуты) |
| `/balance` | группа | ваш настоящий баланс и секунды до начисления (тот же текст, что в личной переписке), ответом на команду (с цитатой), без имени. Не отвечает на сообщения от имени чата (анонимный админ), от ботов и без пользователя. Не чаще раза в 20 секунд на пару (чат, игрок) и не больше 10 ответов в минуту на чат |
| `/help` | везде | короткий список команд для этого типа чата. В группе: пять команд с `@<имя бота>` и строка про личную переписку (если имя бота известно) |
| `/privacy` | везде | ссылка `PRIVACY_URL` (в группе отправляется сообщением, без цитаты) |
| `/developer_info` | везде | контакт `DEVELOPER_CONTACT` и ссылка на политику (в группе без цитаты) |
| `/mydata` | личный чат | присылает файл `mydata.json` с вашими данными (игрок, последние 100 раундов, сведения об участии в беседах без идентификатора чата). Не чаще раза в 60 секунд |
| `/deletemydata` | личный чат | предупреждение и кнопки «Удалить всё» / «Отмена». Подтверждение действует 5 минут, запрос не чаще раза в 30 секунд. Удаляет баланс, историю раундов и участие в рейтингах только у нажавшего; на 30 дней сохраняется хэш идентификатора (без `TOMBSTONE_SECRET` команда отвечает отказом) |

### Ответ на /play в группе (PLAY_MODE)

Бот отправляет в группу сообщение через `send_message`, команду не цитирует (из темы форума отвечает в ту же тему). Три режима:

| Режим | Что приходит в группу |
|---|---|
| `card` (по умолчанию) | в тексте одна эмодзи «🎰», без ссылки и без кнопки; карточку мини-приложения Telegram строит по `GAME_LINK` через параметры предпросмотра ссылки |
| `link` | текст «🎰», обёрнутый в ссылку на `GAME_LINK` (HTML); карточку Telegram строит из этой ссылки |
| `button` | как `card`, плюс кнопка «Играть» (обычная URL-кнопка на `GAME_LINK`) |

Неизвестное значение считается `card`, при старте в лог пишется одно предупреждение. **Не проверено** в настоящем Telegram: строится ли карточка в режиме `card`, когда ссылки нет в тексте сообщения. Если не строится, переключитесь на `link` или `button`.

**Скрытые команды владельца** (нет в меню и в `/help`, работают только у `OWNER_CHAT_ID` и только в личной переписке, остальным молчат): `/backupnow` (копия базы сейчас), `/give <сумма>` (начислить фишки себе), `/giveitem <код> [id игрока]` (выдать косметический предмет из каталога себе или игроку, игрок должен хоть раз открыть игру), `/grantall <сумма> <id> [silent]` и `/grantall confirm <id>` (разовое начисление всем игрокам; перед ним бот сам делает копию базы; после коммита транзакции в фоне уходит объявление во все известные группы, `silent` отключает его). **Перед деплоем, который меняет схему или балансы** (миграции выполняются в `db.init_db` при старте), сделайте `/backupnow` и скачайте копию.

**Группы, где состоит бот** (`bot_chats`): бот запоминает числовой `chat_id` группы, когда его добавляют (событие `my_chat_member`) и при любой команде из группы, и забывает при выходе бота или когда группа недоступна. Нужны только для объявления `/grantall`; хранится число и время, без названия и участников. Webhook регистрируется со всеми типами обновлений, `my_chat_member` приходит сам. Группы, где бот был до этой функции, попадут в таблицу после первой команды из группы.

В группе `/mydata` и `/deletemydata` отвечают «Эта команда работает в личной переписке с ботом». Кнопки удаления работают через обновления типа `callback_query`: webhook регистрируется со всеми типами обновлений, ничего настраивать не нужно.

## Защита от повторной регистрации

Чтобы игрок не мог удалять данные командой `/deletemydata`, заходить заново и каждый раз получать стартовые 1000 фишек, после удаления в течение 30 дней (`REGISTRATION_COOLDOWN_DAYS` в `antiabuse.py`, единственное место, где задан срок) стартовые фишки не выдаются: при новой регистрации баланс 0, доход начисляется поминутно, как у всех. Для этого при удалении в таблицу `deletion_tombstones` записывается только HMAC-SHA256 хэш идентификатора и дата удаления (сам идентификатор не хранится). Записи старше 30 дней удаляются при старте сервиса и при каждом удалении.

**TOMBSTONE_SECRET** — секретный ключ HMAC. Создайте его на своём компьютере и добавьте в Variables (не коммитьте в репозиторий и не показывайте):

```
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

- **Если переменной нет:** `/deletemydata` ничего не удаляет и отвечает «Автоматическое удаление сейчас недоступно» (с контактом из `DEVELOPER_CONTACT`, если он задан), в логе при старте предупреждение. Новые игроки регистрируются как обычно (защиты нет). Игру это не ломает.
- **Если значение изменить:** хэши уже удалённых игроков перестанут совпадать, защита для них перестанет работать (они смогут получить стартовые фишки заново), пока не пройдут 30 дней. Меняйте только при необходимости (утечка ключа).
- **Если ключ утёк:** по хэшу без ключа восстановить идентификатор нельзя, но перебором всех возможных идентификаторов можно проверить, удалялся ли конкретный id. Замените ключ.

В `privacy.html` про это написано в разделах 2, 5 и 6; при смене срока обновите и страницу.

## Резервные копии и восстановление

### Что делает платформа, а что программа
- **Платформа Railway:** расписания копий тома (вкладка Backups: Daily, Weekly и т. п.) доступны только на тарифе Pro, на нашем тарифе их нет, поэтому на них рассчитывать нельзя. Основа защиты: ежедневные копии программы на томе плюс **ручная загрузка копии на компьютер** (см. ниже).
- **Программа (этот сервис):** раз в сутки делает согласованную копию базы встроенным механизмом `sqlite3 Connection.backup()` (а не копированием файла, поэтому копия цела, даже если в базу идёт запись), проверяет её (`PRAGMA integrity_check`, подсчёт строк) и кладёт в `<папка DB_PATH>/backups` (например `/data/backups`). Имена `players-ГГГГММДДTЧЧММССZ.db`; последняя копия также доступна как `latest.db`. Права файлов `600`. Хранятся `BACKUP_KEEP` новейших копий. Первая копия через 60 секунд после старта; если самая свежая моложе интервала (после очередного деплоя), копия пропускается. Если свободного места меньше трёх размеров базы, копия не делается (в логе предупреждение). Если в базу пишут так часто, что копия не успевает завершиться за 2 минуты, она срывается и повторится в следующую проверку.
- В той же фоновой задаче раз в сутки удаляются старые данные (см. ниже). Ни команд бота, ни эндпоинтов для скачивания копий нет: копии нигде не публикуются.

### Переменные (все необязательные)
Неверные значения заменяются умолчаниями, при старте в лог пишется одно предупреждение с именами переменных.

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `BACKUP_ENABLED` | `1` | `0` отключает копии (очистка старых данных продолжает работать) |
| `BACKUP_DIR` | `<папка DB_PATH>/backups` | куда писать копии |
| `BACKUP_INTERVAL_HOURS` | `24` | как часто делать копию, целое не меньше 1 |
| `BACKUP_KEEP` | `7` | сколько новейших копий хранить, целое не меньше 1 |
| `ROUNDS_RETENTION_DAYS` | `30` | сколько дней хранить историю раундов, не меньше 2 (на это время нужна защита от повторов запросов) |
| `CHAT_MEMBER_RETENTION_DAYS` | `90` | через сколько дней без заходов удалять запись об участии в беседе, не меньше 7 |

Очистка удаляет пачками по 1000 строк: `roulette_rounds` старше срока, `chat_members` с давним `last_seen` и просроченные `deletion_tombstones`. Таблицу `players` она не трогает никогда. Эти сроки указаны в `privacy.html` (разделы 5): при изменении обновите и страницу.

### Уведомления владельцу (необязательно)
Чтобы копии не оставались без внимания, бот может писать владельцу в личные сообщения. Включаются переменной `OWNER_CHAT_ID` (числовой идентификатор Telegram владельца; его можно взять из поля `telegram_id` в файле, который присылает `/mydata`). Владелец должен хотя бы раз написать боту, иначе Telegram не даст боту написать первым.

Если переменной нет или значение не положительное целое число, уведомления отключены, при старте в лог пишется одно предупреждение (без значения), сервис работает. В режиме только API (бота нет) ничего не отправляется. Сообщения простым текстом, только даты, размеры и числа: никаких идентификаторов игроков, имён и балансов.

| Сообщение | Когда | Не чаще |
|---|---|---|
| Тревога: копия не создана | после сбоя создания копии | раза в 24 часа |
| Тревога: нет успешной копии больше 48 часов | проверка в той же фоновой задаче | раза в 24 часа |
| Предупреждение о месте | свободно меньше 15% тома или меньше 50 МБ | раза в 24 часа |
| Напоминание скачать копию | с датой, размером и числом игроков, командами скачивания (scp) и проверки | раза в 7 дней |

Общий потолок: не больше 3 сообщений в сутки. Если он исчерпан, сообщение пропускается (в лог пишется предупреждение) и будет предложено при следующей проверке, когда окно освободится. Время последней отправки каждого вида хранится в таблице `service_meta` (ключ и значение, без личных данных; напоминание хранится как unix-время), поэтому перезапуски и деплои не вызывают повторов. Ошибка отправки (например, владелец не запускал бота) пишется в лог только типом, отправка не повторяется в цикле и на работу сервиса не влияет. Если копии выключены (`BACKUP_ENABLED=0`), тревоги о копиях и напоминания не отправляются, предупреждение о месте продолжает работать.

**Предупреждение:** если кредиты Railway кончаются, бесплатный том удаляется через 30 дней вместе с базой и копиями на нём. Поэтому копию на компьютере нужно регулярно обновлять (напоминание раз в неделю для этого и нужно).

### Как скачать копию на компьютер (scp)
Основной способ, он работает у владельца. Один раз зарегистрируйте в Railway публичный SSH-ключ (тот же, которым потом пользуется `scp`):

```
railway ssh keys add --key ~/.ssh/<ключ>.pub
```

Дальше для каждой загрузки (две команды из напоминания бота):

```
scp <домен сервиса>@ssh.railway.com:<папка копий>/latest.db ~/roulette-backups/latest-$(date +%F).db
python3 bot/verify_backup.py ~/roulette-backups/latest-$(date +%F).db
```

- `<домен сервиса>`: хост из `PUBLIC_URL` без `https://` (в напоминании бот подставляет его сам, а если не может определить, пишет `<домен сервиса>`).
- `<папка копий>`: `BACKUP_DIR`, по умолчанию `/data/backups`.
- Если ключ защищён парольной фразой, `scp` сам спросит её в терминале.
- Папку `~/roulette-backups` держите **вне репозитория**, чтобы копия с персональными данными случайно не попала в git.

**Запасной способ** (Railway CLI): `railway volume files list /backups`, `railway volume files download /backups/latest.db ./latest.db`. Эти команды не сверены с документацией Railway, и у владельца они не работают: CLI может не работать с ключом, защищённым паролем, и внутри терминала редактора. Пользуйтесь ими, только если `scp` недоступен.

`verify_backup.py` открывает файл только для чтения, проверяет целостность и наличие таблиц, печатает число строк и дату самой свежей записи (личных данных не печатает). Код выхода 0, если копия исправна, и 1, если проблема.

### Как восстановить, не затирая живую базу
**Не проверено** на настоящем Railway. Порядок:
1. Скачайте копию и проверьте `python verify_backup.py ./latest.db`.
2. Загрузите файл на том под новым именем (**не проверено**: `railway volume files upload ./latest.db /restored.db`).
3. Проверьте его на томе тем же скриптом (или скачайте обратно и проверьте).
4. Временно задайте `DB_PATH=/data/restored.db` и задеплойте. Старую базу `/data/players.db` не удаляйте, пока не убедитесь, что всё работает.
5. После проверки вернитесь к нужному файлу или оставьте восстановленный.

**Напоминание:** копии на компьютере содержат персональные данные игроков. Не пересылайте и не публикуйте их, а скачанные копии храните вне репозитория и удаляйте через 30 дней (так обещано в политике конфиденциальности).

## Режим WAL (необязательно)

Причина: на томе Railway `COMMIT` в режиме по умолчанию (журнал rollback, `synchronous=FULL`) иногда занимает сотни миллисекунд. Режим WAL с `synchronous=NORMAL` делает запись быстрее. Включается флагом, по умолчанию всё как раньше.

- **Включить:** задайте `SQLITE_JOURNAL_MODE=wal` и перезапустите сервис. Режим переключается один раз при старте (в `init_db`), в логе будет строка «SQLite ...: журнал=wal synchronous=normal ...».
- **Откатить:** задайте `SQLITE_JOURNAL_MODE=delete`, перезапустите (база вернётся в прежний режим, данные целы), затем при желании удалите переменную. Простое удаление переменной базу из WAL **не** возвращает: режим сохраняется в файле базы.
- **Версия SQLite:** WAL включается только в версиях без ошибки «WAL-reset» (3.44.6 и новее в ветке 3.44, 3.50.7 и новее в ветке 3.50, 3.51.3 и новее; см. https://www.sqlite.org/wal.html). В остальных версиях при старте будет предупреждение с версией, сервис работает в прежнем режиме. Версию SQLite у Python на Railway покажет та же строка в логе (она не проверена).
- **Файлы:** рядом с базой появятся `players.db-wal` и `players.db-shm`. Это нормально, удалять их вручную нельзя. **Не копируйте один файл `.db`** (без `-wal` вы потеряете последние записи): резервные копии делает программа штатным способом (`Connection.backup`, копия всегда одиночный файл без `-wal` и `-shm`), скачивайте их.
- **Надёжность:** при WAL и `synchronous=NORMAL` после сбоя питания или аварии системы последние зафиксированные транзакции могут откатиться (последние секунды игры), сама база остаётся целой. Если появятся платежи или другие записи, которые нельзя терять, нужна полная синхронизация (`synchronous=FULL`); сейчас такого режима при WAL нет, решать отдельно.

## Зашифрованные копии в Telegram

Раз в неделю бот отправляет вам в личный чат файл `players-<время UTC>.db.enc`: копию базы, зашифрованную **открытым** ключом (PyNaCl `SealedBox`). Закрытого ключа на сервере нет, расшифровать файл можете только вы. Незашифрованной отправки нет ни в каком режиме. Формат файла: 8 байт метки `RBK1` и шифртекст.

### Переменные (необязательные)
| Переменная | По умолчанию | Что значит |
|---|---|---|
| `BACKUP_PUBLIC_KEY` | нет | открытый ключ (base64, 32 байта); без него отправка отключена |
| `BACKUP_SEND_INTERVAL_DAYS` | `7` | как часто отправлять, целое не меньше 1 |
| `BACKUP_SEND_MAX_MB` | `20` | если копия больше, она не отправляется (одна тревога и строка в логе) |

Отправка включена, только если заданы верный `BACKUP_PUBLIC_KEY` и `OWNER_CHAT_ID`; иначе при старте в лог одно предупреждение (без значений). Берётся самая свежая проверенная копия не старше 48 часов, а если такой нет, делается новая. Время последней успешной отправки хранится в `service_meta` (`backup_sent_at`). Первая отправка идёт через минуту после старта, сразу после того как вы задали ключ (так вы проверяете, что всё работает). При сбое повтор и тревога не чаще раза в 24 часа. Пока отправка включена, отдельное недельное напоминание про `scp` не приходит: его заменяет подпись к файлу.

### Как создать ключи (на своём компьютере, не на сервере)
```
bot/.venv/bin/python bot/backup_keys.py generate
```
Команда запишет закрытый ключ в `~/roulette-backup-private.key` (права 600; существующий файл не перезаписывается; путь внутри репозитория запрещён, свой путь задаётся `--out`) и напечатает **только открытый ключ**. Его значение задайте на Railway в `BACKUP_PUBLIC_KEY`. Открытый ключ можно напечатать снова: `backup_keys.py public --key <файл>`. Для этих скриптов нужна PyNaCl: `pip install -r bot/requirements.txt` в окружении `bot/.venv`.

### Где хранить закрытый ключ
В менеджере паролей и во втором надёжном месте (например, на отдельном носителе). **Потеря ключа делает все копии нечитаемыми**, а восстановить ключ нельзя. Никогда не кладите его в репозиторий (`*.key` и `*.enc` в `.gitignore` и запрещены проверкой `scripts/check_repo.py`) и не пересылайте.

### Как проверить
1. Задайте `BACKUP_PUBLIC_KEY` и `OWNER_CHAT_ID`, дождитесь деплоя: через минуту файл придёт в чат с ботом (или отправьте боту скрытую команду `/backupnow`).
2. Расшифруйте (вторым аргументом идёт **путь к файлу** закрытого ключа):
```
python3 bot/decrypt_backup.py ~/Downloads/players-<время>.db.enc ~/roulette-backup-private.key ~/roulette-backups/restored.db
```
Скрипт проверит метку формата, расшифрует (права 600, существующий файл не перезаписывает), выполнит `integrity_check` и напечатает числа строк. При неверном ключе или повреждённом файле он выведет понятное сообщение.

### Скрытая команда /backupnow
Работает только в личном чате и только для `OWNER_CHAT_ID`; остальным бот не отвечает и ничего про них не логирует. Нет в меню и в `/help`. Не чаще раза в 10 минут. Отправляет копию вне расписания и `backup_sent_at` не меняет. Если отправка отключена, владельцу отвечает «Отключено».

### Удаление и ротация
- Включите в чате с ботом автоудаление сообщений (функция Telegram; название пункта в настройках не проверено) или удаляйте файлы вручную не позднее чем через 30 дней (так обещано в политике).
- Ротация ключа: создайте новую пару, задайте новый `BACKUP_PUBLIC_KEY`, деплой. Старые копии расшифровываются **старым** закрытым ключом, поэтому храните его, пока живы эти копии.
- Файл `latest.db` на томе остаётся без шифрования (он доступен только через `scp` по вашему SSH-ключу).

## Проверка на GitHub Actions

Файл `.github/workflows/tests.yml` на каждый пуш в `main`, каждый pull request и по кнопке (Run workflow) запускает:
- **Тесты** (`python run_tests.py` в папке `bot`) на Python 3.9 и 3.12 (две независимые проверки);
- **Проверку репозитория** (`scripts/check_repo.py`): падает, если в индексе git есть `.env`, файлы баз (`*.db`, `*.sqlite*`), ключи (`*.key`, `*.pem`, `id_rsa*`, `id_ed25519*`), папки `.venv` и `backups` или строка, похожая на токен Telegram-бота. Найденное значение не печатается, только путь и номер строки. Локально: `python scripts/check_repo.py` (код выхода 0 или 1).

Тесты на 3.9 и 3.12 идут на Ubuntu 24.04, на Ubuntu 26.04 только на 3.12 (для 3.9 там нет готовой сборки Python); задачи на 26.04 с `continue-on-error` (пока проверка совместимости, красный результат на 26.04 общий итог не ломает; окно миграции `ubuntu-latest` 19.10-19.11.2026).

Результат: вкладка **Actions** репозитория на GitHub, а также отметка (галочка или крестик) рядом с коммитом и в pull request. Workflow не использует секреты и настоящие токены, права только на чтение.

Railway деплоит после пуша независимо от результата проверок: красный крестик деплой не останавливает (**не проверено** по документации Railway; чтобы ждать зелёной проверки, у Railway есть настройка «Wait for CI», её наличие и условия не сверялись).

Версия Python на Railway: по документации Railpack переменная `RAILPACK_PYTHON_VERSION` важнее файла `bot/.python-version` (там `3.9`), поэтому при заданной `RAILPACK_PYTHON_VERSION=3.12` работает 3.12. Тесты на 3.9 нужны для локальной работы, на 3.12 для продакшена.

## Режимы запуска

| Условие | Режим |
|---|---|
| задан `PUBLIC_URL` | **webhook**: бот получает сообщения POST-запросами (продакшен) |
| `PUBLIC_URL` нет, `LOCAL_POLLING=1` | **polling**: бот сам опрашивает Telegram, внутри того же процесса |
| ничего не задано | **только API**, бот отключён (так работают тесты) |

### Осторожно: polling снимает webhook
Режим polling (`LOCAL_POLLING=1`) удаляет webhook у бота: Telegram не отдаёт сообщения одновременно двумя способами. Если запустить его локально с токеном **боевого** бота, бот на Railway перестанет получать сообщения, пока вы не перезапустите сервис (при старте он зарегистрирует webhook заново). Для отладки заведите отдельного тестового бота у @BotFather.

## Локальный запуск

Только API (без бота):

```
cd bot
.venv/bin/python api.py
```

С ботом через polling (тестовый бот!):

```
LOCAL_POLLING=1 .venv/bin/python api.py
```

Адрес по умолчанию 127.0.0.1:8000. На Railway адрес `0.0.0.0` и порт `$PORT` задаются командой запуска в `railway.toml`.
